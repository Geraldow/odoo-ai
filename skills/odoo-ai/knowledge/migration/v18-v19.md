# Migration Guide: Odoo 18 → 19

## Key Breaking Changes

### Mandatory Type Hints
In Odoo 19, type hints for model methods are becoming increasingly important and, in many cases, mandatory for proper framework introspection. This aids in better IDE support and runtime validation.

### SQL() Builder Adoption
The old way of writing raw SQL strings is being deprecated in favor of the `SQL()` builder. This improves security against SQL injection and makes queries more readable and maintainable.

**Old Pattern:**
```python
self.env.cr.execute("SELECT id FROM res_partner WHERE name = %s", (name,))
```

**New Pattern (v19):**
```python
from odoo.tools import SQL
query = SQL("SELECT id FROM res_partner WHERE name = %s", name)
self.env.cr.execute(query)
```

### New Constraint API
The `_constraints` attribute is fully removed in favor of `@api.constrains`. Additionally, SQL constraints are being streamlined for better performance during module upgrades.

### OWL Components Refactoring
Odoo 19 continues the transition to a more functional style in OWL. Many legacy class-based components are being refactored to use the latest OWL features, focusing on signals and better state management.

## Migration Steps

1. **Pre-Migration Audit:**
   - Run the `odoo-bin` with the `--dev=all` flag to catch deprecation warnings.
   - Use the `odoo-ai` upgrade-analyzer to identify potential bottlenecks.

2. **Database Backup:**
   - Always perform a full backup before starting the migration process.

3. **Code Cleanup:**
   - Replace all instances of `_constraints` with `@api.constrains`.
   - Refactor raw SQL queries to use the `SQL()` builder.
   - Update XML views to follow the newer, stricter schema validations.

4. **Testing:**
   - Run all existing unit tests (`TransactionCase`).
   - Perform end-to-end testing of critical business flows (Sales, Inventory, Accounting).

## Peruvian Localization (l10n_pe) Note
Special attention should be paid to the electronic invoicing flow, as SUNAT often introduces changes that Odoo 19 incorporates into its core or localization modules. Verify that the `account_edi` and `l10n_pe_edi` modules are updated accordingly.
