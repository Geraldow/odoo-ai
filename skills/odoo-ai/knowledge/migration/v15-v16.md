# Migration Guide: Odoo 15 → 16

## Key Changes from v15

### Command Class Introduced
Odoo 16 introduces the `Command` class to replace the legacy tuple syntax for x2many operations.

```python
from odoo.fields import Command

# NEW v16 syntax
line_ids = [
    Command.create({'name': 'Line 1'}),
    Command.update(id, {'name': 'Updated'}),
    Command.delete(id),
    Command.link(id),
    Command.clear(),
    Command.set([id1, id2]),
]

# Legacy tuple syntax (0, 0, vals) still works but Command is preferred
```

### attrs DEPRECATED
The `attrs` attribute in XML views is deprecated in favor of direct conditional attributes.

```xml
<!-- DEPRECATED in v16 -->
<field name="partner_id"
       attrs="{'invisible': [('state', '=', 'draft')]}"/>

<!-- v16 RECOMMENDED -->
<field name="partner_id"
       invisible="state == 'draft'"/>
```

## Migration Steps

1. **Update x2many Operations**: Start replacing `(0, 0, vals)` with `Command.create(vals)`.
2. **View Migration**: Begin migrating `attrs` to the new syntax. This is critical as `attrs` is completely removed in v17.
3. **OWL 2.x**: Update custom OWL components to use the OWL 2.x API.

```javascript
/** @odoo-module **/
import { Component, useState, onWillStart } from "@odoo/owl";
import { useService } from "@web/core/utils/hooks";

export class MyComponent extends Component {
    static template = "my_module.MyComponent";
    setup() {
        this.orm = useService("orm");
        this.state = useState({ data: [], loading: true });
        onWillStart(async () => {
            await this.loadData();
        });
    }
}
```

## New Patterns

### Conditional Attributes Reference

| Legacy attrs | New Syntax |
|--------------|------------|
| `attrs="{'invisible': [('f', '=', 'v')]}"` | `invisible="f == 'v'"` |
| `attrs="{'readonly': [('f', '!=', 'v')]}"` | `readonly="f != 'v'"` |
| `attrs="{'required': [('f', 'in', [1,2])]}"` | `required="f in [1, 2]"` |

### Batch Create (Mandatory preparation)
Ensure all `create` methods use the `@api.model_create_multi` decorator, as this becomes mandatory in later versions.

```python
@api.model_create_multi
def create(self, vals_list):
    return super().create(vals_list)
```
