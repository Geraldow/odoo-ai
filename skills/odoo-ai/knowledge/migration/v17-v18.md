# Migration Guide: Odoo 17 → 18

## New Technical Features

### SQL() Builder
Odoo 18 introduces the `SQL()` builder for safe SQL query construction, protecting against SQL injection.

```python
from odoo.tools import SQL

query = SQL(
    "SELECT * FROM %s WHERE company_id = %s",
    SQL.identifier(self._table),
    self.env.company.id,
)
self.env.cr.execute(query)
```

### _check_company_auto
Automatic company consistency validation is now available via a model attribute.

```python
class MyModel(models.Model):
    _name = 'my.model'
    _check_company_auto = True

    company_id = fields.Many2one('res.company', required=True)
    partner_id = fields.Many2one('res.partner', check_company=True)
```

## Recommended Patterns

### Type Hints
Adding type hints to method signatures is highly recommended in preparation for v19.

```python
def calculate_total(self, include_tax: bool = True) -> float:
    return sum(self.mapped('amount'))
```

### allowed_company_ids in Record Rules
Use `allowed_company_ids` instead of the legacy `company_ids` in record rule domains.

```xml
<record id="rule_my_model_company" model="ir.rule">
    <field name="name">My Model: Multi-Company</field>
    <field name="model_id" ref="model_my_model"/>
    <field name="domain_force">[
        '|',
        ('company_id', '=', False),
        ('company_id', 'in', allowed_company_ids)
    ]</field>
</record>
```

## Migration Steps

1. **Adopt SQL() Builder**: Replace raw SQL strings with `SQL()` objects.
2. **Multi-Company Validation**: Use `_check_company_auto = True` and `check_company=True` on relational fields.
3. **Type Annotation**: Start annotating your Python methods with types.
4. **Python Version**: Ensure you are on Python 3.11 or higher (3.12 recommended).

## Checklist for v18
- [ ] Use `SQL()` builder for all manual queries.
- [ ] Enable `_check_company_auto` for multi-company models.
- [ ] Add type hints to all new method signatures.
- [ ] Ensure all `@api.model_create_multi` create methods are properly annotated.
